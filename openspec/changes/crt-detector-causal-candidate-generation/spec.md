## A. Problem statement — the legacy generator is not point-in-time causal

The legacy Line-B candidate-generation pipeline (`primitives.crt_range.detect_crt_ranges` → `entries.model1.detect_model1_signals` → `alignment.htf_ltf.tag_alignment` → `backtest.population.build_stage6_population`, its internal `_dedup`) computes every candidate's existence, identity, and economic fields (`take_profit`, `partial_price`, RR-eligibility) as a function of the **entire** series passed in, not a causal prefix ending at the candidate's own event index (`retest_index = K`). `candidate_cutoff_end_utc` (the statistical runner's existing admission-time filter, REQ-STAT-29) only decides whether an already-computed candidate is admitted into the measured universe — it cannot repair a candidate whose existence or identity was itself computed using candles at or after its own event.

This session re-proved five independent leakage channels on the current, real code (synthetic fixtures only — no real market data):

- **B1 — anchor scan unconditioned on range resolution.** `entries.model1._purge_signals` (`detector/entries/model1.py:64-84`) scans for the LTF anchor via `first_breach_index(candles, crt_range.start_index, crt_range.resolved_at_index, ...)` — the scan window's upper bound is `crt_range.resolved_at_index`, but nothing conditions the anchor's *retest* event (found later inside `_track_anchor`, `model1.py:101-168`) on having occurred no later than `resolved_at_index`. **Proven: 248 hits out of 300 synthetic seeds** where a signal's `retest_index < source_range.resolved_at_index` — the signal's own confirming event precedes the existence of the very CRT range that produced it.
- **B2 — CandidateIdentity is not stable across one additional candle.** Hand-constructed 7-candle synthetic series: at prefix length `n=5` the Candidate is `signal_id='1-2-bearish-purge_engulf-wick'`; at `n=6`/`n=7` the SAME real-world signal (identical `retest_index=4`, `anchor_index=2`, `direction=bearish`) is `signal_id='0-2-...'` — `excluded_duplicate` count goes `0 → 1`. One candle *after* the event flips `CandidateIdentity` (`signal_id` embeds `origin_index` verbatim — `model1.py:27-32`). Simultaneously proven: the existing lookahead test's own dedup-collision key, `(anchor_index, direction, confirmation_type, purge_target)` (`tests/property/test_no_lookahead.py:519-524`), is blind to this — it reports `missing-in-full=[]`, `unequal=[]` on this exact fixture.
- **B3/B4 — Stage6-level phantom events and economic mutation.** Randomized probe, 60 seeds, 26 H4 bars, 16 LTF-per-HTF: **341 phantom events across 58/60 seeds** (a Candidate present in the full-series population, with `retest_index` inside a shorter view's own span, absent from that shorter view's population) plus **7 economic-field mutations** — an identical `(retest_index, anchor_index, direction)` key producing a different `take_profit` value (e.g. `1.1230947619140126 → 1.1223043298682147`) purely from candles appended after the shared event.
- **B5 — the "not-yet-closed" concept exists but is keyed on series length, not event time.** `alignment.htf_ltf.tag_alignment`'s `insufficient_htf_data` gate (`detector/alignment/htf_ltf.py:88-94`) compares `ltf_series.candles[-1].timestamp` — the series' own end — against the relevant HTF candle's close time, and only for the single last HTF index. The codebase already has the "HTF candle not yet closed" concept; it just anchors it to "how much data do we currently have" instead of "what time is the candidate's own event." The existing property test's HTF-aligned truncation (`n_ltf = n_htf * 4`, `tests/property/test_no_lookahead.py:530`) can never exercise a mid-HTF-candle cutoff, which is why B5 is invisible to it.

None of B1–B5 are hypothetical: all five were reproduced against the real, current, committed code this session, using only synthetic Hypothesis/hand-built fixtures — zero real instrument data was read to find or characterize them.

## B. Causal invariants (I1–I4)

These are the correctness properties the new generation path must satisfy. `K` denotes a Candidate's own event index (`retest_index`).

### REQ-CAUSAL-01 — I1: Existence stability
**Given** a causally-generated Candidate universe built from a series prefix ending at some index `N >= K`, **when** the same universe is rebuilt from any larger prefix `N' > N` (still `>= K`), **then** a Candidate whose `retest_index = K` that existed at `N` MUST still exist, unchanged in existence, at `N'` — more data arriving after `K` MUST NOT cause a Candidate settled at `K` to appear or disappear.
- **Provenance**: `HUMAN DECISION` (the human approved the causal-correctness principle this session — "only information observable at the candidate's own event time may determine whether/what/how the candidate exists") constrained by `ENGINEERING DECISION` (the exact prefix/index mechanics below, Sections C–D).

### REQ-CAUSAL-02 — I2: Identity stability
**Given** a causally-eligible Candidate at event index `K`, **when** the universe is rebuilt from any prefix `N' >= K`, **then** its `CandidateIdentity` (`(instrument, timeframe, signal_id, retest_index)`, `backtest/candidate.py:5-17` shape) — in particular the `origin_index` embedded in `signal_id` (`model1.py:27-32`) — MUST be identical to what a prefix ending exactly at `K` would produce. This directly closes B2: a second, later-resolving CRT range MUST NOT be permitted to compete for `_dedup`'s survivor slot (`backtest/population.py:86-92`, `min(group, key=origin_index)`) using information unavailable at `K`.
- **Provenance**: `HUMAN DECISION` + `ENGINEERING DECISION` (as REQ-CAUSAL-01).

### REQ-CAUSAL-03 — I3: Economic-field stability
**Given** a causally-eligible Candidate at event index `K`, **when** the universe is rebuilt from any prefix `N' >= K`, **then** every field computed at generation time — `direction` and `entry_type` (already proven anchor-determined and series-length-independent by REQ-CAUSAL-11's `_track_anchor` analysis), plus `entry_price`, `stop_loss`, `take_profit`, `partial_price` (`backtest/candidate.py:14-17`) — and the RR-floor test that gates admission (`population.py::_rr_floor_cut`) MUST be identical to what a prefix ending exactly at `K` would produce. This closes B3/B4: `take_profit`'s dependence on `htf_context` (`population.py::_build_candidate` line 50) must resolve to the SAME HTF context regardless of candles appended after `K`.
- **Provenance**: `HUMAN DECISION` + `ENGINEERING DECISION`.

### REQ-CAUSAL-04 — I4: Eligibility stability
**Given** a Candidate that was admitted or excluded (`excluded_no_crt_range`/`excluded_unaligned`/`excluded_never_confirmed`/`excluded_no_key_level`/`excluded_duplicate`/`excluded_kill_zone`/`excluded_rr_floor` — `backtest/population.py::Stage6Population`) at event index `K`, **when** the universe is rebuilt from any prefix `N' >= K`, **then** its admitted/excluded status and exclusion reason MUST be identical to what a prefix ending exactly at `K` would produce.
- **Provenance**: `HUMAN DECISION` + `ENGINEERING DECISION`.

### REQ-CAUSAL-05 — Explicitly permitted exception: fill/exit/outcome
**Given** I1–I4 govern candidate GENERATION (existence, identity, economic fields, eligibility), **when** a Candidate is subsequently filled, held, or exited by `backtest.simulate.simulate()`, **then** fill/exit/outcome fields (`entry_index`, `exit_index`, `exit_price`, `outcome`, `r_multiple`, and related) MAY depend on candles strictly after `K` — that is the entire purpose of a backtest simulator, and `crt-detector-direction-policy-statistical-runner`'s `outcome_followup_end_utc` (REQ-STAT-29(c)) already governs exactly this boundary. I1–I4 are never violated by an outcome depending on later data; they are violated only if generation itself does.
- **Provenance**: `ENGINEERING DECISION` (scope boundary, needed so I1–I4 are not misread as forbidding backtesting itself) + `REPO CONVENTION` (mirrors the existing `outcome_followup_end_utc` boundary already frozen in the runner spec).

### REQ-CAUSAL-06 — Named exception: legacy intra-candle-K approximation
**Given** `evaluation.direction.evaluate_direction_policies` requires `BiasEvidence` at exactly `cutoff = candidate.retest_index - 1` (`detector/evaluation/direction.py:130-136`) — i.e. DirectionPolicy's own decision boundary is `K-1`, one candle before the candidate's retest close — **when** the causal generator computes admissibility and economics at `K`, **then** this pre-existing `K-1` boundary convention (inherited unmodified from Line-A/Layer-2, out of this change's scope) is NOT itself a violation of I1–I4: it is a already-frozen, already-shipped approximation of "what's knowable at the candidate's own event," not a new leakage channel this change introduces or is responsible for closing.
- **Provenance**: `ENGINEERING DECISION` (scope carve-out, stated explicitly so a future reviewer does not mistake this pre-existing convention for a defect this change failed to fix).

## C. LTF visibility rule (R-strict)

`primitives.crt_range.CRTRange.resolved_at_index` (`detector/primitives/crt_range.py:16`) is the field this rule is built on: this session's predecessor design pass proved, by exhaustive synthetic comparison (17,700 prefixes, 0 violations), `detect_crt_ranges(series.up_to(n)) == {r in detect_crt_ranges(full_series) : r.resolved_at_index <= n-1}` — i.e. `resolved_at_index` is exactly the index at which a `CRTRange` becomes causally knowable. This is not invented for this change; it is the existing field's own proven semantics.

### REQ-CAUSAL-07 — LTF admission rule: R-strict
**Given** a candidate LTF CRT range `R` and a prospective Model-1 signal it could produce with event index `K` (`retest_index`), **when** the causal generator decides whether `R` may participate in generating that signal, **then** `R` is admissible **iff `R.resolved_at_index <= K - 1`** (R-strict, the human-confirmed rule over the rejected R-loose alternative `<= K`) — a range that resolves AT or AFTER the candidate's own event index MUST NOT be permitted to produce, compete for, or alter that candidate's identity or economics. This directly closes B1 (the anchor-scan channel) and B2 (the identity-flip channel): a later-resolving competing range at the same anchor is inadmissible at `K` by construction, so it can never enter `_dedup`'s survivor competition for that candidate.
- **Provenance**: `HUMAN DECISION` (R-strict chosen explicitly over R-loose this session) constrained by `ENGINEERING DECISION` (deriving the rule from `resolved_at_index`, the field the design-pass 17,700-prefix proof grounds it in — not an invented boundary).

## D. HTF visibility rule (H-A) — and why the literal-preserving alternative is degenerate

`alignment.htf_ltf._enclosing_htf_index` (`detector/alignment/htf_ltf.py:231-238`) returns the HTF candle whose own timestamp is `<=` the LTF anchor's timestamp — i.e. the HTF candle CONTAINING the LTF anchor, which is **still open** at LTF event time. The legacy pipeline then requires that same (still-open) HTF candle to *also* be the resolved purge candle of some `CRTRange` (`_purge_index_map`, `htf_ltf.py:211-228`) — a candle can only be a "purge candle" once its owning range has resolved (`resolved_at_index >= purge_index`, since `purge_index` is found by `first_breach_index(candles, start, resolved_at_index, ...)`, `crt_range.py:19-38` scanning `(start, resolved_at_index]`).

### D1. Why the literal-preserving alternative (H-B) is proven degenerate

A causally faithful reading of "only use the HTF candle that literally contains the LTF anchor" (H-B) would require BOTH: (a) `purge_index == relevant_index` (the literal enclosing candle, unchanged) AND (b) `htf_close(resolved_at_index) <= t` (the range's resolution must itself be observable by LTF event time `t`). Since `purge_index` and `resolved_at_index` belong to the same range and `resolved_at_index >= purge_index` always holds, requiring both (a) and (b) together forces `resolved_at_index == purge_index` — i.e. the range must resolve on the SAME candle that purges it. This eliminates every `false_break` (Turtle Soup) HTF context outright (a false break's `resolved_at_index` is, by `_resolve`'s own logic, `crt_range.py:99-109`, strictly later than the poke/purge candle) and eliminates the majority of `true_break` contexts too (any true break resolving later than its own first breach). **H-B is degenerate — it deletes the HTF alignment concept for false breaks entirely**, which the mentorship-derived methodology treats as a first-class context (Turtle Soup is one of the five TSQ phases per `docs/charter-4.md`). This is a proof, not a preference: H-B was evaluated and rejected on structural grounds, not on style.

### REQ-CAUSAL-08 — HTF visibility rule: H-A
**Given** an LTF signal's event time `t`, defined precisely as the timestamp of the LTF candle at `retest_index = K` — Section B's own event-index convention, the same `K` every causal invariant (I1–I4) is stated relative to — and explicitly NOT the anchor's earlier timestamp (legacy `tag_alignment`'s current HTF-lookup key, `htf_ltf.py:81-82`, which this rule supersedes for causal purposes: keying off the anchor would be needlessly stricter than I1–I4 actually require, since `anchor_index < K` always holds), **when** the causal generator selects the LTF signal's HTF context, **then** the selected `CRTRange` MUST be the resolved HTF range with the LARGEST `purge_index` among all HTF ranges satisfying `htf_candles[R.resolved_at_index].timestamp + htf_duration <= t` (i.e. the HTF candle at `resolved_at_index` has fully closed by `t`) — ties broken by lowest `start_index` (mirrors the existing earliest-established-range tiebreak already used by `_purge_index_map`, `htf_ltf.py:217-218`, "the earliest-established range... wins as the more likely intended HTF context"). This is the ONLY viable causal HTF rule (Section D1); it is a direct, forced consequence of the human-approved "only information observable at LTF event time" principle (Section B), not an independent design choice with alternatives still open.
- **Provenance**: `HUMAN DECISION` (the causal-correctness principle, approved this session) + `ENGINEERING DECISION` (H-A's exact mechanics — the "most recent purge among resolved-and-closed ranges" selection and its tiebreak — is the unique way to instantiate that principle without degenerating per D1).

## E. CV-D architecture — bounded-state single chronological pass

### REQ-CAUSAL-09 — Bounded state machine
**Given** the causal generator must never re-run full detection per candidate (which would be `O(n^2 * 40)` at this repo's real ~100k-candle scale — infeasible), **when** it processes a series chronologically, **then** it MUST maintain only bounded state: open (unresolved) LTF CRT range candidates capped by `CRTRangeConfig.max_lookback` (`core/config.py:16`, default 20), in-flight LTF anchor trackers capped by `2 * Model1Config.max_retest_lookback` (`core/config.py:38`, default 20 — the factor of 2 bounds simultaneously-tracked purge_engulf and fvg_fill anchors), and a monotonically-advancing HTF pointer for H-A's "most recent resolved-and-closed range" lookup — never the full candle history re-scanned per event. This preserves the existing pipeline's own `O(n * (max_lookback + max_retest_lookback)) = O(n * 40)` order (same complexity class as today's full-series pass), with leakage horizons bounded at `<= 20 * 15min = 5h` (LTF) and `<= 20 * 4h = 80h` (~3.3 days, HTF).
- **Provenance**: `ENGINEERING DECISION`, constrained by the repo's own existing `DetectorConfig` bounds (`PREREGISTERED` only in the sense that `max_lookback`/`max_retest_lookback` are pre-existing repo defaults, not new values invented here).

### REQ-CAUSAL-10 — Package placement and import-linter enforcement
**Given** Line-A (the legacy generator) must stay frozen and provably unaffected, **when** the causal path is implemented, **then** it MUST live in a NEW root package `detector/causal/`, sibling to `evaluation`/`selection`/`adapter` in `.importlinter`'s `root_packages` list (`detector/.importlinter:2-15`) and `pyproject.toml`'s `[tool.hatch.build.targets.wheel]` packages list, and TWO new `forbidden` import-linter contracts MUST be added mirroring the existing `no-adapter-in-upstream-layers`/`no-selection-in-outcome-layers` pattern (`.importlinter:97-123`): (a) `research` MUST NOT import `causal` (mirrors `no-policy-in-research`'s intent — Line-A's exploratory research code must not silently consume the new causal path), and (b) `evaluation` MUST NOT import `causal` (mirrors `no-selection-in-outcome-layers` — the outcome-evaluation seam stays a pure consumer of whatever population it is handed, never a source of causal-generation logic). No existing contract's `source_modules`/`forbidden_modules` list is edited — only two new `[importlinter:contract:...]` sections are added, plus `causal` appended to `root_packages`.
- **Provenance**: `ENGINEERING DECISION` (package placement, architecture D-A from the design pass — recommended over the three alternatives compared there) + `REPO CONVENTION` (mirrors the existing sibling-package-plus-forbidden-contract pattern used for `selection`/`adapter`).

## F. Non-impact proofs — what stays frozen, and why

Each of these guards against scope creep into Line-A/Layer-2/Layer-1 code. Each proof is independent of whether generation is causal or legacy.

### REQ-CAUSAL-11 — `_dedup` needs no change
**Given** `backtest.population._dedup` (`detector/backtest/population.py:86-92`)'s key `(anchor_index, direction, entry_price, entry_type)` and survivor rule `min(group, key=origin_index)`, **when** the causal generator produces its candidate list, **then** `_dedup` MUST be reused UNCHANGED — proof: `entries.model1._track_anchor` (`model1.py:101-168`) computes `entry_type`/`entry_price` (via `_select_entry`) and `retest_index` as pure, deterministic functions of `(candles, anchor_index, direction, config)` alone; `origin_index`, `purge_target`, and `confirmation_type` are stored on the resulting `Model1Signal` but never read by `_track_anchor`'s own computation. Consequently any two candidates colliding on `_dedup`'s key necessarily share the identical `retest_index`, and `take_profit` (from `htf_context`, a function of `anchor_index` alone per `population.py::_build_candidate` line 50) is likewise shared within a dedup group — only `signal_id` (via `origin_index`) can differ. The defect (B2) was purely upstream, in what SET of competing signals reaches `_dedup`, never in `_dedup`'s own logic.
- **Provenance**: `ENGINEERING DECISION` (the proof), confirmed against the current committed code, not assumed.

### REQ-CAUSAL-12 — `simulate()` is a drop-in consumer
**Given** `backtest.simulate.simulate()` (`detector/backtest/simulate.py:282-296` calls `build_stage6_population`; `_fill_pass` uses `eligible_at = retest_index`), **when** the causal generator's output (a `list[AlignedSignal]`, same shape as the legacy path's) is passed to `simulate()`, **then** NO change to `simulate()` is required — it never re-detects signals, it only fills/resolves an already-built population against the (full, for outcome purposes per REQ-CAUSAL-05) series.
- **Provenance**: `ENGINEERING DECISION`, confirmed by reading `simulate.py`'s actual call graph.

### REQ-CAUSAL-13 — `DirectionEvaluation` needs no change
**Given** `evaluation.direction.evaluate_direction_policies` (`detector/evaluation/direction.py:118-139`) reads only `population.series` (identity-checked via `evidence.series is candidate_series`, line 84), `population.candidates`, and per-candidate `direction`/`retest_index`/`origin_index`/`anchor_index`/`signal_id` (validated at lines 105-114: direction in `{bullish, bearish}`, `retest_index >= 3`, `0 <= origin_index <= anchor_index < retest_index < len(series.candles)`, identity uniqueness, dense `BiasEvidence` for `1..len(candles)-1`), **when** a causally-generated `Stage6Population` is passed to it, **then** NO change to `evaluation/direction.py` is required — it never reads `htf_context` and never assumes how the population was built, only that it satisfies the constraints already enforced at lines 102-115.
- **Provenance**: `ENGINEERING DECISION`, confirmed line-by-line against the current committed code.

### REQ-CAUSAL-14 — `CandidateIdentity` shape stays frozen
**Given** `CandidateIdentity`'s frozen shape `(instrument, timeframe, signal_id, retest_index)` (defined in `crt-detector-direction-policy-statistical-runner/spec.md` Section A, mirroring `backtest/candidate.py:5-17`'s `Candidate.signal_id`/`retest_index` fields), **when** the causal generator computes `origin_index` (embedded in `signal_id`), **then** the TYPE/SHAPE of `CandidateIdentity` MUST NOT change — under R-strict admission (REQ-CAUSAL-07), the set of ranges observable at `K` is fixed once `K` is reached and never grows, so `min(origin_index)` over that fixed set is permanently stable. Only the VALUE's provenance narrows ("lowest `start_index` among ranges observable at `K`" replaces "lowest `start_index` among all ranges ever detected") — the field's meaning to every downstream consumer (Layer-2's `TradeJoinKey`, Layer-1's opaque `CandidateIdentity`) is unaffected.
- **Provenance**: `ENGINEERING DECISION`, direct consequence of REQ-CAUSAL-02/07.

## I. Line-A isolation strategy

- **Provenance**: `ENGINEERING DECISION`, an explicit inventory constraint carried over verbatim from the design pass's own confirmed file list.

### REQ-CAUSAL-18 — Deterministic Line-A behavioral fingerprint test

- **Provenance**: `ENGINEERING DECISION`, `REPO CONVENTION` (mirrors this repo's existing hash-pinning idiom, e.g. the Amendment JSON's own SHA-256 pin in `crt-detector-direction-policy-statistical-runner/spec.md`).

## J. New property-test oracle — causal-path-only

### REQ-CAUSAL-20 — `tests/property/test_causal_no_lookahead.py`
**Given** the existing lookahead oracle `test_alignment_detection_has_no_lookahead` (`tests/property/test_no_lookahead.py:502-547`) keys signal identity by `(anchor_index, direction, confirmation_type, purge_target)` (line 519-524) — proven blind to the B2 identity-flip class (Section A) because that key omits `origin_index` — **when** the new causal path is tested, **then** a NEW oracle MUST be written that matches by `(retest_index, anchor_index, direction)` — the causal EVENT-anchored key, never `signal_id` (which embeds the very `origin_index` under test) and never `origin_index`/`purge_target` directly (which would trivially pass by construction rather than testing stability) — and MUST assert BOTH directions of stability, unlike the legacy test's one-directional check: (a) **no disappearance** — a causally-admissible candidate present in a shorter causal run remains present, with identical `CandidateIdentity` and economic fields (I1–I3), in every longer causal run; AND (b) **no phantom creation** — a candidate absent from a shorter causal run's admissible set never "was actually there all along" once more data resolves (i.e. no candidate whose event index `K` is within the shorter run's causal horizon appears only in the longer run). The oracle's HTF prefix MUST be derived by H-A's own closure rule (REQ-CAUSAL-08: "HTF candle at `resolved_at_index` has fully closed by `t`"), NOT by lockstep truncation (`n_ltf = n_htf * 4`, the existing test's approach, `test_no_lookahead.py:530`) — lockstep truncation cannot express a mid-HTF-candle cutoff, which is exactly what B5 (Section A) requires the oracle to be able to construct.
- **Provenance**: `ENGINEERING DECISION` (oracle design) constrained by `REPO CONVENTION` (mirrors this repo's existing Hypothesis-based no-lookahead property-test family's structure and naming, `test_no_lookahead.py`).

### REQ-CAUSAL-21 — Legacy failing test stays frozen as historical evidence
**Given** `tests/property/test_no_lookahead.py::test_alignment_detection_has_no_lookahead` currently FAILS against the legacy (non-causal) pipeline (this is the reproduced counter-example both this change's design pass and the statistical runner's V5 Section Q rely on), **when** this change is implemented, **then** that test MUST be left UNTOUCHED — not deleted, not weakened, not marked `xfail` to silence it — and classified in this change's own test documentation as `LEGACY CAUSALITY FAILURE — KNOWN — NOT ACCEPTABLE FOR NEW LINE-B CAUSAL PATH`. It MUST NEVER be used as the acceptance gate for the new causal path (REQ-CAUSAL-20's new oracle is the gate for that); it remains, permanently, documented evidence of the legacy generator's proven non-causality, which is this change's own reason to exist.
- **Provenance**: `ENGINEERING DECISION` (documentation/classification), `HUMAN DECISION` (implicit in the human's approval of this change's problem statement, which rests on this exact failing test).

## K. T-e — outcome-free population check is NOT a precondition, and MUST NOT gate rule-freezing

**Correction to this spec's original framing** (made explicit here rather than silently rewritten): an earlier draft of this section treated T-e as a `build-preflight` precondition that implementation "must not cross unchecked." That framing was wrong and is retracted — it would have made the acceptability of R-strict/H-A depend on inspecting real population size, which is exactly the kind of outcome/population-derived tuning of a frozen rule that the DirectionPolicy Discovery line's entire preregistration discipline exists to forbid. Corrected below.

### REQ-CAUSAL-22 — Causal semantics are frozen and implemented from code + synthetic evidence alone; no real-data gate
**Given** R-strict (REQ-CAUSAL-07) and H-A (REQ-CAUSAL-08) are each already justified by a code-grounded proof (the 17,700-prefix `resolved_at_index` identity for R-strict; the H-B degeneracy proof for H-A) and by synthetic-only reproduction of the leakage channels they close (Section A), **when** this change is implemented, **then** implementation MUST proceed directly from this spec's frozen rules — no inspection of real Candidate population size, real aligned-rate, or any other real-data-derived quantity may be used to decide whether R-strict/H-A are "acceptable," to adjust either rule, or to gate whether implementation may begin or be considered complete. Real-data population size is irrelevant to whether these rules are CORRECT — correctness was established from causal-structure proofs (Sections C/D), never from a population-size observation, and it MUST stay that way to preserve the same preregistration discipline `crt-detector-direction-policy-statistical-runner` already freezes for itself (REQ-STAT-17 "no optional stopping," REQ-STAT-34 "no post-hoc allowlisting").

**T-e (the design pass's "real-data population-magnitude check") is downgraded from a precondition to, at most, an OPTIONAL, non-gating, strictly outcome-free verification**, permissible only under all three of:
(a) it runs AFTER this change's causal generator is implemented and its own synthetic acceptance gate (REQ-CAUSAL-20) is green — never before or in place of implementation;
(b) it runs, if at all, BEFORE any `crt-detector-direction-policy-statistical-runner` measurement-execution baseline or real discovery run is authorized — it belongs to that spec's own pre-baseline authorization checklist, never to this change's implementation or sign-off;
(c) it is defined so its result CANNOT feed back into changing R-strict, H-A, or any other rule this spec freezes — it may report only a Candidate count and an aligned-rate per instrument (never any outcome/`realized_r`-derived quantity, never a WR/EST-B/nomination-adjacent figure), and a low count MUST route to a separate, explicit human decision about whether the underlying METHODOLOGY needs reconsideration — never to a silent parameter change made to produce a larger population.

**This spec is NOT blocked, gated, or held unsigned by T-e's absence.** Implementation of `crt-detector-causal-candidate-generation` may begin and complete using synthetic evidence only, exactly as this design pass and this spec already have.
- **Provenance**: `HUMAN DECISION` (this correction — the human explicitly rejected T-e as an implementation precondition and required that causal-rule freezing depend only on code + synthetic evidence, never real-population inspection) + `ENGINEERING DECISION` (the outcome-free, non-rule-revising reporting contract, if T-e is ever run at all — re-scoped from the design pass's original framing).

## L. Open parameter — HTF lookback window `W`

**Given** the design pass left H-A's HTF lookback window `W` (how far back H-A's "most recent resolved-and-closed range" search may reach) unbounded by default, **then** this V1 freezes `W = unbounded` (search the entire causally-observable HTF history, no artificial cap) as its default. This is an `ENGINEERING DECISION`, not a `HUMAN DECISION` — the human was not asked to choose a numeric bound, and none is silently invented here. A future pass MAY introduce a bounded `W` (for memory/performance reasons at very long HTF histories) as an explicit, separately-reviewed amendment; V1 does not need one because REQ-CAUSAL-09's bounded-state analysis already shows the HTF pointer itself is a single monotone cursor, not an unbounded buffer — "unbounded `W`" means "the search may reach arbitrarily far back," not "state is retained unboundedly." **`W` governs ONLY how far BACK into HTF history H-A's search may reach — it never grants, implies, or permits access to any HTF candle not yet causally observable at `t`; that categorical boundary is REQ-CAUSAL-08's closure condition, which applies independently of `W` and is never relaxed by it.** `W` MUST NOT be implemented as, or confused with, any form of future/lookahead access.
- **Provenance**: `ENGINEERING DECISION`, explicitly labeled as a default subject to later revision, never a silently-frozen numeric choice.
