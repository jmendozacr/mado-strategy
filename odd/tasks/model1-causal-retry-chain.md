## Specs

- **S1 — Authorization (user, verbatim)**: "Trabajemos en lo que te dije y si es posible resolvamos el bug también" — authorizes implementing the retry-chain spec below and addressing the no-lookahead bug.
- **S2 — Retry-chain mechanics (user, verbatim, paraphrased across two messages)**: "en 15 minutos si la siguiente vela supera el low ese current anchor queda invalidado y pasa a ser el siguiente el current anchor" — on LTF, when a candle's close breaches the current anchor's protected extreme, that anchor becomes `INVALIDATED` but the breaching candle becomes the new current anchor and tracking continues (no terminal stop on first invalidation).
- **S3 — Retry-chain stop condition (user, verbatim)**: "cuando se deja de validar current anchor, si supera el low de HTF o si la vela actual de 4H termina superando el Low de la vela de 4H que queríamos purgar" — the chain stops only when the owning HTF range's purge target is itself truly broken (the HTF candle closes beyond the level it was purging). User explicitly confirmed (next message) these are **one condition, not two**: "Correcto no son 2 chequeos independiente, lo entendiste bien." This is exactly `primitives.crt_range._resolve`'s existing `"true_break"` classification, computed on the HTF range.
- **S4 — Direction symmetry and timing (user, verbatim)**: "si fueran ventas sería el high, porque el modelo uno puede suceder al principio o más tarde siempre y cuando haga la purga, toque un key level" — mirror low/high for bearish; Model-1 may confirm on the first anchor or several anchors later in the chain, as long as it still purges and touches the credited key level.

## Context established this session (not specs — findings, cited for the next task to reconcile against)

- **Bug (Engram #470) root cause, confirmed**: `entries.model1._purge_signals` runs `_track_anchor` once per undeduped LTF CRT range; two overlapping ranges with different `start_index` can independently claim the same `anchor_index` as their first breach, so `origin_index`/`signal_id` are unstable across a truncated vs. full series. Already fixed, but only in `causal/signals.py::causal_purge_engulf_signals` (R-strict admissibility + `min(start_index)` dedup) — `entries/model1.py` itself is deliberately **frozen**: `openspec/changes/crt-detector-causal-candidate-generation/spec.md` REQ-CAUSAL-21 (`HUMAN DECISION`) says the legacy failing test (`tests/property/test_no_lookahead.py::test_alignment_detection_has_no_lookahead`) must stay failing, permanently, as documented evidence — never patched, never silenced.
- **`cli.py` still wires up the legacy path** (`cli.py:15,22,208,247` — `tag_alignment`/`detect_model1_signals`), not `causal/`, so the bug is live in what the user actually runs despite the fix existing, unused, elsewhere.
- **`causal/generate.py::generate_causal_aligned_signals` is NOT yet a drop-in replacement for `cli.py`'s needs** — two concrete gaps found by reading it in full:
  1. It never sets `AlignedSignal.key_level_reaction` (always `None`) — legacy `tag_alignment` populates it via `_purge_reaction` (`alignment/htf_ltf.py:118,143-154`). `causal/generate.py` already imports from `alignment.htf_ltf`, so reusing `_purge_reaction` is not a layering problem.
  2. It only emits signals with `retest_index is not None` (`generate.py:62-63`) — every PENDING-without-retest or pre-retest-INVALIDATED signal is silently dropped. Legacy `cli.py` reports every status in `detections.csv` (`cli.py::_exclude_invalidated_model1`'s own docstring: "detections.csv keeps every status") and `_detect_all` needs a flat `model1_signals` list, not just the joined `AlignedSignal`s `generate_causal_aligned_signals` returns.
- **`.importlinter` ADR-01 layering**: `alignment` sits above `entries`; `causal/` already imports from both `entries` and `alignment` (confirmed in `causal/generate.py`/`causal/signals.py`), so the retry-chain's HTF-bounded stop condition belongs in `causal/`, composed over unmodified `entries.model1._track_anchor`/`_purge_signals` — never by changing `_track_anchor` itself, which `causal/signals.py`'s own causal-correctness proof (REQ-CAUSAL-11) explicitly relies on staying "a pure function of `(candles, anchor_index, direction, config)` alone."
- Mapping/diagnosis done via one read-only exploration agent this session (general-purpose, task "Map Model-1 retry-chain gap and diagnose lookahead bug") plus direct reads of `cli.py`, `causal/htf.py`, `causal/ranges.py`, `causal/state.py`, `causal/generate.py`, `causal/signals.py`, `alignment/htf_ltf.py`, `primitives/crt_range.py`, `tests/property/test_no_lookahead.py`.
