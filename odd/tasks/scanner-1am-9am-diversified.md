- **S4 — Both reaction types are alerted, not just `reject_close_inside`**: the user's own validated backtest (428 combined trades, 60.7% WR, +$30,345 at $10k/1%) includes BOTH `reject_close_inside` AND `continuation` reactions (confirmed this session: `find_turtle_soup_triggers`/`backtest.population._population_cuts` never gate on reaction type). The OLD scanner recipe's `filter_new_alerts` silently dropped every non-`reject_close_inside` candidate (`scanner/rules.py` line 41) — that filter must NOT carry over into the new recipe, or live alerts would represent a different, unvalidated, worse-performing population than what was backtested and approved.
- **S5 — No separate session/kill-zone gate needed in `rules.py` for the new recipe**: each model's own confirmation window (`causal.htf_trigger.confirmation_window_utc`/`ltf_window_indices`) already bounds which M15 candles can ever produce a signal — by the time a `Candidate` exists, it is already inside a valid 1AM or 9AM window. The OLD recipe's fixed `_in_session` (02:00-11:00 NY) check is specific to that recipe's own London+Lunch+NY design and must not be reused for this one.
- **S6 — Architecturally independent of the open H-A credit-selection bug** (verified in code this session, confirming the user's own correction): `causal/htf_trigger.py` imports only `alignment.htf_ltf._key_level_credit_map`/`_purge_reaction` (single-known-range crediting, no retroactive multi-range tie-break) — it never imports `causal/htf.py`/`select_htf_context`, so the standing decision at Engram #816 (this branch must not reach the live scanner while H-A is broken) does not block THIS specific addition. That decision is NOT reopened or resolved here — the old EURUSD recipe's own path through `cli._detect_all`/`generate_causal_aligned_signals` (which DOES use the H-A-affected code) is being REMOVED by this change (S1), not fixed.
- **S7 — Reuse, never reimplement**: `backtest.simulate.simulate`/`backtest.population.build_stage6_population`/`backtest.metrics.compute_metrics` stay unchanged, exactly as the existing scanner's own docstring already requires for its old recipe.
