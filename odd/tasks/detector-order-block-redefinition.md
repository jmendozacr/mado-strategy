## Specs

- **S1 — Motivation, verbatim from the triage (engram #514, 2026-09-05).** The archived sub-change #2's `detect_ict_order_blocks` is a pure 2-candle engulfment test with no notion of impulse or structural break. A chart-review session this conversation (2026-11-07/08) independently re-derived the same gap and measured it on real data: `experimental/order_block_structural_break_check.py` found only ~25-27% of detected OBs are followed by a real structural break (MSS, same direction) before invalidating, consistent across EURUSDm H4/M15/Daily and GBPUSDm H4.
- **S2 — Full definition, as specified in the triage** (reopens archived spec V4, REQ-61-64/66/67): Market Structure (Swing High/Low, HH/HL/LH/LL) -> BOS (configurable close/wick confirmation) -> Displacement (body-vs-ATR multiplier, configurable, up to N candles) -> backward scan from displacement start for the last OPPOSING candle within a configurable lookback cap -> that candle is the Order Block. Lifecycle: active -> mitigated -> invalidated (configurable mitigation/invalidation criteria). Hard no-repaint/no-lookahead requirement across the whole chain (raw index vs first-knowable index, matching SEAM-02's own `origin_index` convention).
- **S3 — Architectural risk resolution (user-confirmed this session, no objection raised to the stated recommendation).** BOS reuses `composite.mss.detect_mss_events` AS-IS, unmodified — the user's chosen BOS confirmation (close-based) is exactly what `detect_mss_events` already implements (its `decisive_close_ratio` threshold is close-based by construction), so no wick-confirmation mode needs building for this change. The redefined OB detector lives in `composite/` (not `primitives/`), consuming `composite.mss` as a sibling module in the same `.importlinter` layer — no layering change needed, both already sit in `composite | entries`.
- **S4 — User decisions this session (verbatim choices from `AskUserQuestion`, 2026-11-08):**
  - BOS confirmation: **close-based** (a candle must CLOSE beyond the opposite swing to count as a decisive break) — matches `composite.mss`'s existing behavior exactly.
  - Mitigation: **touch** (any wick touching the zone marks it mitigated/already-used) — informational on `ICTOrderBlock`, does NOT end the zone's life as a Key Level (only invalidation does — S6).
  - Invalidation: **close beyond the zone** (a candle must CLOSE past the zone's far edge) — stricter than the archived detector's current rule (any wick-or-body overlap invalidates).
  - Zone bounds: **wick-to-wick** (candle.high/candle.low of the anchor candle), confirmed against the user's own TradingView chart annotations earlier this session (exact match, no hand padding) — NOT the archived detector's current body-only (`open`/`close`) zone.
- **S5 — Defaults this session chose from existing repo precedent (not asked as open questions, stated and unobjected):** Displacement = body-sum over <=3 candles >= 1x ATR14, identical to `research/displacement.py`'s frozen constants (cannot import that module directly — `research` must never be imported by production per `.importlinter`'s `no-research-in-production` contract — so this is a small, independent production-side reimplementation of the same test, not a reuse-violation). Backward-scan lookback cap = 20 candles, matching `Model1Config.max_retest_lookback`'s existing precedent.
- **S6 — KeyLevel mapping.** `origin_index` = the first index at which the OB is provably knowable (after displacement confirms, never the geometric anchor candle's own index — SEAM-02 convention). `expiry_index` = the invalidation index (S4) — mitigation is tracked on `ICTOrderBlock` but does not end Key-Level validity.
- **S7 — Scope discipline (triage's own PM flag, carried forward):** this change redefines ONLY `ict_order_block`. Do not build `crt-detector-breaker-block` (sub-change #3) even if a shared kernel looks reachable. Do not reopen Rejection Block or the Turtle-Soup/Model-1-in-zone idea (both explicitly out of scope per `project/pending-changes`).
- **S8 — Walking-skeleton acceptance, before any production wiring.** Build the new detector in isolation (new files only, zero production files touched — same discipline as every other probe on this branch) and re-run `experimental/order_block_structural_break_check_runner.py` against it on real EURUSDm/GBPUSDm data. The real-break-confirmation rate should be dramatically higher than the archived rule's measured ~25-27% baseline; swapping it into `cli.py`/production (reopening the signed spec, re-verifying `viz/chart.py`/`viz/table.py`/SEAM-01/02 consumers) is a separate, later, higher-risk step — not part of this skeleton.
