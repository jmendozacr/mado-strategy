Memory #782 (Order Block's own null result) explicitly predicted "by the same logic likely a future Breaker Block source too" would show zero outcome change, because FVG dominates `_key_level_credit_map`'s highest-origin_index tiebreak (~117k of ~120k credits) almost regardless of the competing source's individual quality — so this measurement also exercises `alignment/htf_ltf.py`'s existing opt-in `credit_priority` override (ranking `breaker_block` above the rest) as a second arm, to test the dominance hypothesis directly rather than only confirm or refute it indirectly.

  ```
  without breaker          signals=56288  trades=684  win_rate=0.4825 avg_r=+0.2839 total_r=+194.21 credits={fvg:116277, ict_order_block:2207}
  with breaker (recency)   signals=56358  trades=685  win_rate=0.4818 avg_r=+0.2821 total_r=+193.21 credits={fvg:107554, breaker_block:8959, ict_order_block:2177}
  with breaker (priority)  signals=56358  trades=685  win_rate=0.4818 avg_r=+0.2821 total_r=+193.21 credits={fvg:107157, breaker_block:10470, ict_order_block:1063}
  ```
  **Confirms #782's prediction.** Default (recency) tiebreak: +1 trade, total_r -1.00 (-0.5%) — a null result within noise. Forcing `breaker_block` to win every tiebreak via `credit_priority` (the direct test of the FVG-dominance hypothesis) moves its raw credit share 5x (8959→10470) and nearly halves Order Block's (2177→1063), yet produces **byte-identical** `trade_stats` to the recency arm (685/0.4818/+0.2821/+193.21) — so even when breaker_block wins almost every tiebreak it is eligible for, the final `reject_close_inside`-filtered, simulated outcome does not move at all. Breaker Block's ~9-10k credits overwhelmingly land on signals that already had an FVG or OB credit anyway (coverage overlap, not new territory) — only 1 of 56288 signals net-changed between "without" and "with breaker."
  **Caveat, unrelated to breaker block itself**: the "without breaker" control (684 trades, total_r +194.21) does NOT reproduce memory #782's own cited baseline (1014 trades, total_r +445.08) on what should be the same wiring and data. `Model1Config` defaults are unchanged (`core/config.py:35-38`); the likely cause is the `entries/model1.py`/`backtest/simulate.py`/`backtest/levels.py` changes `main` picked up between #782 (2026-11-08) and this branch's pull (`2e34a57`) — not investigated further, out of this task's scope, but it means absolute magnitudes here are not directly comparable to #782's, only the three arms run in this same session against each other are.
  **Recommendation to the user**: do NOT add `breaker_block` to the production Daily-tier Key Level pool as currently wired — it changes the backtest outcome by less than noise even in its best-case (forced-priority) arm, for the same structural reason Order Block's own 3x quality gain was invisible (#782). If Breaker Block is still wanted, the lever is the credit-pooling/tiebreak mechanism itself (`alignment/htf_ltf.py::_key_level_credit_map`, option (c) the user did not pick this round), not another source added to the current winner-take-all pool.
