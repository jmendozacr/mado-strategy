Objective: port the already-designed-but-never-shipped Breaker Block Key Level source (`core/key_level.py`'s own "Breaker Block later" placeholder) onto current `main`, then measure — through the exact pattern already used for Order Block (`experimental/order_block_redefinition_backtest.py`, memory #782) — whether adding it to the Daily-tier Key Level pool changes the live recipe's real backtest outcome, to decide whether it belongs in the production key-level list.

## Specs

- **S1 — Breaker Block detector, ported to current `main`.** Mado's Breaker Block is a FAILED Model-1, flipped — charter-4 [00:07:35]: "La vela que termina siendo el Breaker Block es, en el momento en que se forma, la misma vela que los traders leyeron como un Modelo 1 válido... pero en realidad era un Modelo 1 falso (fake Model 1) que los dejó atrapados operando en la dirección equivocada." Charter-5 [00:01:59]: "el precio cierra por encima de un máximo a corto plazo... activando la fase de Breaker Block" — activation is the decisive close through the trapped level. Charter-4 [00:07:45]: "El retest a esta vela ofrece una zona de rechazo de alta probabilidad." A reference implementation already existed on the unmerged `detector-feeder-chain-dol-entries` branch (commits `0233f03`/`de7ec16`) but that branch diverged too far from current `main` (`entries/model1.py`, `backtest/population.py`, `composite/ict_order_block.py` all changed independently on both sides since) for a direct cherry-pick — ported fresh against `main`'s actual shapes instead, same domain logic: one `BreakerBlock` per `Model1Signal` with `status == INVALIDATED`, zone = the trapped anchor's own body, `activation_index = signal.confirmation_index` (verified at `entries/model1.py:150` — overwritten to the breach candle's index on invalidation), direction flipped from the trapped signal's own direction.
- **S2 — `KeyLevel.kind` extended (additive).** `core/key_level.py`'s `Literal["fvg", "ict_order_block"]` gains `"breaker_block"`, plus a `to_key_levels` adapter in `entries/breaker_block.py` mirroring `composite/ict_order_block.py`'s own (`origin_index=activation_index`, `expiry_index=retest_index`, right-closed per `alignment.htf_ltf._key_level_credit_map`'s own expiry test).
- **S3 — Measure the real impact, mirroring the OB experiment (user's explicit choice, see L2).** User, verbatim (L1): "exploremos que tenemos acerca de breaker block para hacer las debidas pruebas y ver si lo incluimos a nuestra lista de key levels." Given a choice between (a) a cheap coverage-only measurement, (b) repeating the OB experiment's full real-backtest comparison, or (c) questioning `_key_level_credit_map`'s pooling/tiebreak mechanism first, the user picked **(b)** — same harness pattern as `experimental/order_block_redefinition_backtest.py`: swap only the Daily-tier Key Level pool through `entries.model1.detect_model1_signals` → `alignment.htf_ltf.tag_alignment` → `backtest.simulate.simulate`, unmodified, on real EURUSDm data. Memory #782 (Order Block's own null result) explicitly predicted "by the same logic likely a future Breaker Block source too" would show zero outcome change, because FVG dominates `_key_level_credit_map`'s highest-origin_index tiebreak (~117k of ~120k credits) almost regardless of the competing source's individual quality — so this measurement also exercises `alignment/htf_ltf.py`'s existing opt-in `credit_priority` override (ranking `breaker_block` above the rest) as a second arm, to test the dominance hypothesis directly rather than only confirm or refute it indirectly.
